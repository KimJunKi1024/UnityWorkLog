# 작업 기록 패키지 설계 (2026-11-12)

## 목적
엘라린 프로젝트의 작업 기록 도구(`ClaudeCode/WorkLog/add_worklog.py`)를 커밋 도구 Git Sync처럼 Unity 패키지로 만들어,
다른 Unity 프로젝트도 `Packages/manifest.json`에 한 줄을 넣어 쓰게 한다.

## 결정 (사용자)
- 새 저장소 `UnityWorkLog`, 패키지 `com.teamelarin.worklog` (Git Sync와 따로 설치·버전 관리)
- 공용 설정(`ProjectSettings/WorkLogSettings.json`: 항목 폴더·MD·HTML 상대 경로·제목) + PC별 작업 기록 폴더(자동 탐색, 직접 지정 가능)
- Unity 안에 설정 화면 + 기록 창
- 테스트는 새 빈 프로젝트에서, 드라이브에 테스트 프로젝트용 새 MD·HTML을 만들어 확인
- 엘라린은 이번에 바꾸지 않음 (기존 `add_worklog.py`·문서 명령 유지)

## 하지 않는 것
- 엘라린 전환, GitHub 저장소 생성·푸시(사용자 확인 뒤 따로)
- 항목 형식 변경 (예전 항목·번호를 그대로 이어 씀)

## 구성
| 파일 | 역할 |
|---|---|
| `Tools~/worklog_add.py` | 항목 → MD·HTML 추가. 예전 도구 로직 그대로 + 설정 읽기·빈 파일 틀·`--next`·`--init` |
| `Tools~/worklog_template.html` | 새 HTML 틀 (엘라린 HTML의 스타일·스크립트, 탭 비움) |
| `Editor/WorkLogSettings.cs` | 공용 설정 읽기·쓰기 |
| `Editor/WorkLogLocalSettings.cs` | PC별 작업 기록 폴더(`UserSettings/WorkLogLocal.json`)·Python 경로(EditorPrefs) |
| `Editor/WorkLogTools.cs` | 도구를 `Library/WorkLog/Tools/`로 복사, 백그라운드 실행, Python 자동 탐색 |
| `Editor/WorkLogEntry.cs` | 항목 파일 읽기·쓰기·검사 |
| `Editor/WorkLogSettingsProvider.cs` | 설정 화면 |
| `Editor/WorkLogWindow.cs` | 기록 창 |
| `Tests~/test_worklog.py` | 파이썬 도구 테스트 (예전 도구와 결과 비교 포함) |

## 확인 방법
1. `python "Tests~/test_worklog.py"` — 빈 기록 생성, 번호·형식 오류 중단, 설정 읽기, 예전 도구와 같은 결과(엘라린 기록 복사본)
2. 새 빈 Unity 2022.3 프로젝트에 로컬 경로로 설치 → 배치 모드 컴파일 오류 0
3. 드라이브에 테스트 프로젝트용 MD·HTML을 만들어 실제 추가
